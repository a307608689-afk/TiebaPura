# 渐显带不满宽（右缘缺一条竖带）排查与修复 — 维护文档

> **适用工程**：TiebaPura（HarmonyOS，ArkTS / ArkUI 原生，API 26）
> **方案版本**：v1.0（落地日期：2026-09-14）
> **实证页面**：收藏页（`pages/Favorite.ets`）四个列表界面；排查历时四轮修复。
> **姊妹文档**：`floor-vanish-viewport-fix.md`（虚拟滚动容器视口剔除，同属"沉浸 + 滚动容器"场景）。

---

## 1. 现象特征（如何识别同类问题）

沉浸式列表（`clip(false)` + `expandSafeArea`）顶部挂「整页 DST_IN 透明度遮罩」实现渐显带时：

- 渐显带**不满宽**：右缘有一条**竖直分界线**，分界线右侧的区域完全**没有渐隐效果**（内容清晰、颜色更实）；
- 分界线位置**全屏恒定**（不随卡片边距变化），截图放大后竖直边缘非常明显；
- **同一段代码，平板正常、手机异常**（或反过来）——宽度解析问题最典型的"部分设备才触发"；
- 把遮罩在列表 / 包裹容器之间搬来搬去（挂点回迁）**全部无效**；
- 给外层包裹容器补 `width('100%')` 也**无效**（见 §3 第 3 轮）。

**识别关键词**：`linearGradient` + `BlendMode.DST_IN` + `BlendApplyType.OFFSCREEN` 组成的整页透明度遮罩 + 挂在滚动容器（`List` / `Scroll` / `WaterFlow`）的 `overlay` 上 → 疑似同源问题。

## 2. 原实现（问题代码）

```ts
// 整页 DST_IN 遮罩：顶部 topFadeStop 区内容渐隐，其余全实
@Builder
BottomFadeOverlay() {
  Stack()
    .width('100%')
    .height('100%')
    .linearGradient({
      direction: GradientDirection.Bottom,
      colors: [['#00FFFFFF', 0.0], ['#FFFFFFFF', this.topFadeStop()], ['#FFFFFFFF', 1.0]]
    })
    .blendMode(BlendMode.DST_IN, BlendApplyType.OFFSCREEN)   // ← 问题组合
    .hitTestBehavior(HitTestMode.None)
}

// 挂在滚动容器上
List({ ... }) { ... }
  .overlay(this.BottomFadeOverlay())
  .blendMode(BlendMode.SRC_OVER, BlendApplyType.OFFSCREEN)   // ← 配对使用
```

原理：`DST_IN` 让列表内容按遮罩 alpha 绘制（遮罩 alpha 0 = 内容透明）→ 内容滚入顶部渐隐区时"渐现/渐隐"。该方案在多个页面跑过数个版本，**手机上部分场景离屏层宽度解析异常**（见下），且异常与页面结构强耦合、极难定位。

## 3. 排查过程（四轮，前两轮方向性错误）

| 轮 | 假设 / 做法 | 结果 |
|---|---|---|
| 1 | 渐显带下移盖到内容 + 缺块 → 把遮罩从滚动容器移到带 padding 的包裹 Column（"首尾让位区对齐"） | **更糟**：缺块仍在 + 遮罩宽明显不满屏 → 回退 |
| 2 | 怀疑容器自身宽度 → 滚动容器 / 包裹 Column 补 `width('100%')`、`layoutWeight` 显式化 | **无效** |
| 3 | 怀疑宿主宽度 → 给所有 `Refresh` 补显式 `width('100%')`（Refresh 未挂显式宽度时，内部 `width('100%')` 相对 Refresh 测量成循环、解析为**内容固有宽**） | **部分改善但手机仍缺块**（平板转正常）→ 说明还叠加了别的问题 |
| 4 | **判定 `DST_IN + OFFSCREEN` 离屏层宽度在手机上解析异常**（平板正常 = 设备/形态相关，与挂点无关）→ **放弃整页遮罩方案**，改「Stack 顶层满宽背景色渐变条」（§4） | **解决** |

### 核心教训

1. **`blendMode(·, OFFSCREEN)` 的离屏缓冲宽度 = 系统解析值，不可信**。它可能取"内容固有宽"而非组件布局宽，且**只在部分设备 / 部分容器嵌套下触发**——凡用整页 DST_IN 遮罩做渐显，就要做好"某天在某设备上右缘缺一块"的准备。
2. **`Refresh` / `Tabs` 等包裹型容器必须显式 `width('100%')`**：内部百分比子项相对它测量，未显式宽度时会解析成内容固有宽。这是第 3 轮抓到的**独立真实 bug**（即使换掉遮罩方案也要修），但不是缺块的全部原因。
3. 挂点回迁（遮罩在滚动容器 / 包裹容器之间搬）对离屏层宽度问题**完全无效**——先判断是不是离屏层问题：**同代码平板正常手机异常（或某设备正常某设备异常）≈ 离屏层 / 宽度解析问题**，直接换方案，别再调挂点。

## 4. 终版方案（当前落地代码）

**思路**：下层是纯背景色时，"内容渐隐"与"背景色渐变条叠加"**视觉等价**——放弃挖洞，改叠加。宽度跟随一个**已被实证全宽**的层（页面根 `Stack`，页面背景满宽正常就是证据），彻底不依赖滚动容器 / 离屏层的宽度解析。

```ts
/**
 * 顶部满宽渐显带：挂页面根 Stack 顶层（zIndex 8）。
 * 高 132 = TopBar 98 + 分段切换区 ~34（只盖按钮与标题区，不盖内容卡片）。
 * 渐变必须【从顶部即线性渐变、无全实段】——见 §5 硬切教训。
 */
@Builder
TopFadeBand() {
  Column()
    .width('100%')
    .height(132)
    .linearGradient({
      direction: GradientDirection.Bottom,
      colors: [
        [Theme.bg(this.isDark), 0.0],                    // 顶部：背景色全实（该区被悬浮顶栏盖住，无感知）
        [this.isDark ? '#00101114' : '#00F2F4F7', 1.0]   // 底部：同色 alpha 00（= 全透明，线性渐隐）
      ]
    })
    .hitTestBehavior(HitTestMode.None)                   // 不挡列表点击
    // .zIndex(8)  ← 若与被盖元素同层才需要；本例挂 Stack 末位 + 其它浮层自带 zIndex
}
```

挂在页面根 `Stack`（`alignContent` 为顶部系）的**子项序列末尾**（绘制在最上），`zIndex` 低于悬浮控件：

| 层 | zIndex | 说明 |
|---|---|---|
| 列表内容 | 0（被渐显带覆盖） | 渐显带要盖的对象 |
| **渐显带** | 8 | 本体 |
| 兜底分段胶囊行 | 13 | 在带之上 |
| 编辑操作栏 | 15 | 在带之上 |
| 槽位顶栏（Navigation title） | title 层天然高于内容区 | 不受影响 |

**原列表上的 `.overlay(遮罩)` 与 `.blendMode(SRC_OVER, OFFSCREEN)` 全部移除**（`clip(false)` / `expandSafeArea` / padding 保留）。

### 适用条件与边界

- **下层必须是纯背景色**：渐变条是"用背景色盖内容"，若列表下层有图片 / 渐变 / 非纯色层，叠加条会露馅 → 此时只能回到挖洞方案（并接受 §3 的风险）或让条颜色精确匹配下层。
- **暗色模式**：背景色与透明尾色都要按 `isDark` 切换（透明尾 = 同色 alpha `00`，如 `#F2F4F7` → `#00F2F4F7`）。
- **覆盖高度**：建议 `TopBar 高 + 分段区高`（本项目 132vp），或按"视口高 × 比例"夹取——**不要**按视口高 20% 这类与首卡位置无关的算法（曾导致渐隐区下探盖到首卡顶部）。

## 5. 硬切教训（渐变参数）

首版渐变 `[[bg, 0.0], [bg, 0.5], [transparent, 1.0]]`（前半段全实）→ 内容一进入条顶就被**完全不透明背景色盖死**，到 50% 处才突然开始渐现 → 用户反馈"内容到顶栏像被**硬切**了一样"。

**规则：渐变必须从顶部（0.0）就开始线性渐变，禁止任何全实段**。顶部较实的部分应落在悬浮顶栏自身的覆盖范围内（本项目 0~98vp 被顶栏盖住，无感知），其余部分全是平滑渐变——与挖洞式"内容从顶栏下渐现"观感一致。

## 6. 快速排查清单（下次直接用）

1. **渐显带右缘缺竖带**：先确认遮罩是不是「整页 DST_IN + OFFSCREEN」→ 是，且同代码在别的设备 / 形态正常 → **直接换 §4 背景色渐变条方案**，不要再调挂点。
2. **换方案前顺手修**：页面里所有 `Refresh` / `Tabs` 等包裹型容器是否挂了显式 `width('100%')`（独立真实 bug，见 §3 第 3 轮）。
3. **换方案后若"内容到顶被硬切"**：检查渐变 stops 是否含全实段 → 改为从 0.0 开始线性（§5）。
4. **层级自检**：渐显带 zIndex 必须低于所有悬浮控件（编辑栏 / 分段行 / 顶栏），高于列表内容；`hitTestBehavior(None)` 必挂。
5. **暗色模式自检**：背景色与透明尾色双份切换；切深色后渐显带颜色必须跟着变。
6. **适用条件自检**：下层是纯背景色才能用叠加条；下层有非纯色层时禁用（§4 边界）。
