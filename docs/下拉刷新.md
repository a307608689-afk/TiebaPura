# 下拉刷新

> 沉淀自 2026-09-22 下拉刷新落地过程（进吧页 / 消息页），含指示器位置调节的完整试错与定稿结论。
> 参考实现：
> - `pages/HomeTab.ets` 推荐页、`pages/MessagesTab.ets` 回复/提到我的、`pages/ForumsTab.ets` 进吧页、
>   `pages/ThreadList.ets` 吧主页（热门/最新/精选）—— **定稿写法：Refresh margin 下移 + 系统默认指示器**（§3.1）。
>   已接入页面的 `Refresh` 顶部让位量：首页/消息/进吧 98（消息页 `NOTIFY_TOP_PAD`）、吧主页 90（`THREAD_LIST_HEADER_TOP_SPACE`）。

## 一、基本接入范式

`Refresh` 组件包住滚动容器（List / WaterFlow / Scroll 均可），三件套：

```ts
Refresh({ refreshing: this.pullRefreshing, offset: 48, friction: 62 }) {
  List({ scroller: this.listScroller }) { /* ... */ }
  .width('100%')
  .height('100%')
}
.width('100%')
.layoutWeight(1)                    // 在 Stack 中用权重铺满；Column 中同理
.onRefreshing(() => { this.onPullRefresh(); })
```

- `offset`：**下拉触发刷新的距离**（vp）。它只控制"拉多远触发"，**不控制指示器的停靠位置**（见 §三）。
- `friction`：阻尼，62 与首页推荐页一致，跟手手感已验证。
- 触发时框架调用 `onRefreshing`，收起时机完全由绑定的 `refreshing` 变量控制（见 §二）。

## 二、坑 1：指示器永远转圈不停（必须显式走 true→false 变化沿）

**症状**：下拉能触发刷新，但转圈一直不停。

**根因**：Refresh 收起指示器的条件是绑定的 `refreshing` 变量出现 **true→false 的变化沿**。
如果 `onRefreshing` 里只做业务、结束时才把变量写 `false`，而变量此前从未被置过 `true`
（框架不保证把 true 回写进普通 `@State`），结束那次赋值就是 false→false——没有变化沿，指示器永远停住。

**正解**（与首页推荐页 `loadHomeThreads` 同款）：进入刷新处理函数**第一步显式置 true**，`finally` 置回 false：

```ts
private async pullRefreshForums(): Promise<void> {
  this.pullRefreshing = true;                       // ⚠️ 必须显式置 true，制造 false→true→false 变化链
  const watchdog: number = setTimeout(() => {
    this.pullRefreshing = false;                    // 看门狗：弱网/接口挂起时强制收起
  }, 15000);
  try {
    await this.doRefresh();                         // 内部自行 try/catch，不向外抛
  } finally {
    clearTimeout(watchdog);
    this.pullRefreshing = false;
  }
}
```

配套纪律：
- 刷新函数内部**自行消化异常**（catch 后保持旧数据），保证 `finally` 必达；
- 加 **15s 看门狗**兜底，任何网络挂起都不会永久转圈。

## 三、指示器位置：定稿方案 = margin 下移 Refresh 区（系统默认指示器）

**结论先行**：系统默认指示器**锚在 Refresh 容器顶边**，`offset` 只控"拉多远触发"、**不控指示器位置**
（想靠加大 offset 把图标推下去是无效尝试）。要让转圈出现在头部控件（胶囊 / 标题栏）下方，
唯一实测协调的做法是**把整个 Refresh 容器下移到头部之下**——首页推荐页就是这么做的，消息页已对齐同款。
自定义 builder 调位置试过三种写法、真机全部失败（见 §3.3 反面教材），不要再用。

### 3.1 正确写法（首页推荐页 / 消息页同款）

```ts
Refresh({ refreshing: this.pullRefreshing, offset: 48, friction: 62 }) { /* 列表 */ }
.width('100%')
.height('calc(100% - 98vp)')       // ⚠️ 定高扣除下移量（margin+layoutWeight 会底部溢出，见 §四）
.margin({ top: NOTIFY_TOP_PAD })   // ⬅ 下移到头部控件之下：指示器随之出现在其下方
.onRefreshing(() => { this.pullRefresh(); })
```

配套两条：
- **头部让位要同步交接**：原有的内容 padding-top 让位 / 顶部占位 ListItem 改为 0 或移除，由 margin 接管，
  保证内容初始起点与改动前逐像素一致；
- `offset` 保持 **48**（与首页一致），触发点与指示器停靠位置随即与首页统一。
- 指示器外观 = 系统默认（不传 `builder`）；外观与位置都由这一个机制统一解决。

### 3.2 代价：内容不再滚进头部区域（沉浸取舍）

margin 方案下列表顶格在头部件下方，滚动时内容不会出现在透明材质标题栏后面：

| 页面形态 | 结论 |
|---|---|
| 头部是浮动胶囊、内容本来就顶格在其下方（首页推荐/关注动态、消息页回复/提到我的） | **无副作用，推荐**（已落地） |
| 内容刻意延伸到页顶、在透明材质标题栏下滚动（进吧页这类沉浸式页面） | 会产生「顶部不沉浸」的观感退化（实测被用户打回） |

此类沉浸页若必须保沉浸，目前**没有既保沉浸又把默认指示器下移**的官方手段
（Refresh 只有 offset / friction / builder 三项可配，offset 无效、builder 见 §3.3），需产品侧二选一。

### 3.3 反面教材：不要用自定义 builder 调位置（三种写法真机全败）

builder 内容在「下拉露出区」里**贴底排布**（底边贴着内容顶、随拉拽距离浮动），定位行为不可控。
实测三种写法全部被真机打回：

| 写法 | 现象 |
|---|---|
| 根容器 `padding({ top: 100 })`（配 offset 130） | 无明显效果；小拉距时转圈顶进状态栏区（投诉 1） |
| 固定高度条 + `justifyContent(End)`（条高 = offset） | 刷新期转圈位置仍随露出区浮动、跑到最上面（投诉 2） |
| 根容器 `height('100%')` + `position({ y })` 钉固定 y | 位置终于固定，但指示器层**非刷新态也常驻绘制** → 转圈一直显示并在转、切 Tab 仍残留（投诉 3） |

**结论：builder 可以用于「换外观」，不能用于「控制刷新起止位置」。要位置就按 §3.1 用 margin。**
（如需自定义外观又想位置正确：只能在外观已正确的前提下用 builder 只做样式，不要在 builder 内做位移。）

### 3.4 选型口诀（定稿）

| 页面形态 | 做法 |
|---|---|
| 头部浮动、内容顶格在其下方（首页推荐/关注动态、消息页回复/提到我的） | **margin 下移 + 系统默认指示器**（§3.1）✅ 已落地 |
| 内容需延伸到材质标题栏下滚动（进吧页） | 同样改用 margin + 默认指示器（2026-09-22 用户拍板：位置优先，接受内容不再滚进标题栏之下）✅ 已落地 |
| 吧主页（热门/最新/精选，ThreadList） | **沉浸页的正解 = margin + `Refresh.clip(false)` + 页面层背景色渐变带**：①Refresh `margin 90` + `.clip(false)`（不裁切 → 列表内容可溢出到顶栏之下渲染，沉浸的关键；首页同款）；②顶部渐显带从「容器内 DstIn + 页高 15%」改为**页面层背景色渐变条、只罩按钮区 108vp**（原方案在容器 margin 后整体下移压到吧头）；③内容让位从内容移到 margin，故 `captureExitSnapshot` 裁剪量改为容器局部坐标、旧页快照层 `translate.y` 加回 90 ✅ 已落地 |
| 精选分类页（GoodCategoryPage） | 同款：Refresh margin `GOOD_TITLE_BAR_HEIGHT=88`；内容让位交接（多列档保留 `GOOD_TOP_EXTRA=12` 的额外首行留白、单列档置零）；原 `refreshing: $$` 双向绑定保留 ✅ 已落地 |
| 我的帖子 / 我的点赞 / 浏览历史（PersonalContent，mode 参数区分三态） | 同款：Refresh margin `98`；`loadItems(silent=true)` 复用同一条加载管线（不切 Loading、失败保留旧列表只 toast）；顶部渐显带（容器高度比例）随容器下移会压到首卡，一并移除 ✅ 已落地 |

## 四、坑 2：margin 与 layoutWeight 叠加导致底部溢出

给 Refresh 加 `margin({ top: X })` 时，若高度仍用 `layoutWeight(1)`（在 Stack 中），
权重分配的高度不含 margin，实际足迹 = 权重高 + margin，底部会溢出 X。两种解法：

- 定高：`.height('calc(100% - Xvp)')` + `.margin({ top: X })`（工程内 calc+vp 语法已验证可用，首页推荐页与消息页即此写法）；
- 或不用 margin（指示器位置无从下移，见 §3.3）。

## 五、坑 3：插入 @Builder 方法会把相邻 builder 的装饰器隔断

在 `@Builder ForumsContent()` 前插入新的 `@Builder` 方法时，若只插在装饰器与方法名之间，
原装饰器会落到新方法上、原 builder 裸奔，组件语法整体解析炸出成串 `';' expected`。
**正解**：插入时把「doc 注释 + @Builder + 方法」作为整体搬运，保证每个 builder 各自带 `@Builder`。

## 六、刷新逻辑范式（不闪屏、可对账）

下拉刷新的用户体感要求"列表保持在场"，与冷启动加载不同：

- **不切 Loading 态**：保持当前列表渲染，网络落地后整体替换 `@State` 数组（不可变更新），失败静默保留旧数据；
- **复用静默刷新通道**：进吧页 `await refreshFollowsSilently(true)`（force 绕过 60s 节流），
  消息页 `await loadMessages(tab, true, true)`（silent=true 保列表、第 1 页整体替换），
  与切 Tab 对账、关注/取关广播共享同一条数据管线，避免多份刷新代码漂移；
- **带乐观增量对账**：若页面存在"本地先改、服务端后到"的操作（如关注/取关），网络返回后要
  保留未同步的乐观增量（限时 10 分钟），防止滞后接口把本地状态洗掉；
- 刷新入口同时顺带刷新页内其它轻量数据（如足迹本地缓存直出）。
