# 帖子预加载 — 交付说明

> **适用工程**：TiebaPura（HarmonyOS 7 / API 26，ArkTS / ArkUI 原生）
> **覆盖页面**：首页 `HomeTab`（推荐 / 关注动态双 feed）、吧主页 `ThreadList`（含吧内搜索态）、关注列表 `FollowList`、
> 收藏内帖子列表 `Favorite`、我的内容 `PersonalContent`（帖子 / 点赞 / 收藏 / 历史）、他人主页 `UserProfile`（帖子 / 关注的吧双列表）
> **日期**：2026-09-19（二批：偏移口径修正 + 判定收口 `PrefetchGate`）
> **状态**：✅ **已落地**（真机效果良好）

---

## 1. 背景与目标

### 1.1 问题

改造前三处帖子流列表都用**底部哨兵触发**分页（ArkUI 的 `onReachEnd`）：

- `onReachEnd` 只在**滚动真正触底**（或接近底部）时才回调；
- 回调后还要**发起网络请求 + 等响应**，这段时间列表尾部是空的（或只有"加载中"）；
- 用户**快速甩滑**时，翻页请求永远追不上手指 —— 表现为「滑到底部卡一下 / 空白一段才出新内容」，即所谓**触底停顿感**。

### 1.2 目标

把「触底才请求」改成「**快触底就提前静默请求**」，让下一页在用户滑到底之前就已经拼接好，实现**触底无缝续流**（连续滑到底也感觉不到加载）。

### 1.3 设计原则

| 原则 | 落地 |
|---|---|
| **提前量** | 距底部剩余距离 < 阈值（约 2 屏）即触发，覆盖一次请求的耗时窗口 |
| **零感知** | 预加载走**静默模式**（`silent = true`）：失败不弹 Toast，靠触底兜底重试 |
| **不重复** | 三重防重：**状态锁**（`loadingMore`）+ **偏移节流**（120vp）+ **请求代际**（`loadToken`） |
| **不误报** | 触底（用户主动）仍走 `onReachEnd` 兜底，只有它失败才提示用户 |
| **不改行为** | 只提前**发起时机**，分页逻辑 / 数据合并 / 去重口径全部沿用原实现 |

## 2. 核心机制：剩余距离预加载

三处列表共用同一套模型，仅阈值与测量方式略有差异。

### 2.1 触发条件

```
剩余距离 = 内容总高 − 视口高 − 当前偏移
        = contentH − viewportH − y

触发预加载 ⇔ 剩余距离 ≤ PREFETCH_DISTANCE
```

- `contentH`：滚动内容的**总高度**，由 `onAreaChange` 实测回填（虚拟容器按条数折算，见 §2.5）。
- `viewportH`：滚动**视口高度**，同样由 `onAreaChange` 实测。
- `y`：当前滚动偏移，**必须取 `Scroller.currentOffset().yOffset` 真值**（`PrefetchGate.absoluteY(scroller)`）。

> ⚠️ **不要用 `onScroll` 的回调入参当 `y`**（2026-09-19 修正）：其语义在工具链 / 组件类型之间存在差异
> （`Scroll` 上曾观测到帧增量语义），一旦它不是绝对偏移，「剩余距离」就会被算成恒小于阈值的错值 ——
> 表现为**预取要么每滚一下都触发（疯狂翻页）、要么永不触发（滑到底空一段才加载）**。
> 正解是只信 `Scroller.currentOffset()`，这也是帖子详情页 `ThreadDetail.onDetailScrollPrefetch` 一直在用的口径。

即：**还差约 2 屏到底时**就请求下一页。

### 2.2 阈值常量

| 页面 | 常量 | 值（vp） | 说明 |
|---|---|---|---|
| 首页（推荐 / 关注动态） | `HOME_PREFETCH_DISTANCE` | **1200** | `HomeTab.ets` 顶部 |
| 吧主页 | `THREAD_PREFETCH_DISTANCE` | **1200** | `ThreadList.ets` 顶部 |
| 收藏内帖子列表 | `THREAD_PREFETCH_DISTANCE` | **1000** | `Favorite.ets` 类内静态常量 |
| 我的内容（帖子/点赞/收藏/历史共用一个常量） | `PERSONAL_PREFETCH_DISTANCE` | **1000** | `PersonalContent.ets` 顶部 |
| 他人主页（帖子 / 关注的吧共用） | `PROFILE_PREFETCH_DISTANCE` | **1000** | `UserProfile.ets` 顶部 |
| 关注列表 | `FOLLOW_PREFETCH_DISTANCE` | **1000** | 行高估算口径，略小 |
| 全站搜索（搜吧 / 搜贴 / 搜人共用） | `SEARCH_PREFETCH_DISTANCE` | **1200** | `Search.ets` 顶部 |
| 帖子详情（既有口径参照） | `DETAIL_PREFETCH_DISTANCE` | **1600** | `ThreadDetail.ets` 顶部 |

> 1200vp ≈ 2 屏（手机单屏约 600–700vp），足够覆盖一次翻页请求的往返耗时，让快速甩滑时新数据"刚好"在到位前拼上。

### 2.3 三重防重

预加载发生在**滚动回调**里，会被高频触发，因此必须防重：

1. **状态锁**
   - 首页：`homeLoadingMore` / `folLoadingMore`
   - 吧主页：`loadingMore`
   - 关注列表：`loadingMore`
   - 请求进行中直接 `return`，避免同一页被并发请求多次。

2. **偏移节流**（120vp）＋**判定收口**

   判定不再在各页面手写，统一走 `common/PrefetchGate.ets`（单点维护，节流基线 `lastY` 初值 `-1` = 首轮必放行）：

   ```ts
   if (this.prefetchGate.should(PrefetchGate.absoluteY(this.scroller), contentH, this.viewportH)) {
     this.loadMore(true);
   }
   ```

   `should()` 内部即「几何未测到 → 不放行；剩余距离 > 阈值 → 不放行；偏移变化 < 120vp → 不放行」，
   并在触发时打一条 `[PREFETCH] <tag> FIRE ...` 日志供真机自证；`reset()` 在刷新 / 切 feed / 切排序 / 换列表时复位基线。

3. **请求代际 token**（`loadToken`）
   - 刷新 / 切 feed / 切换排序时 `loadToken++`；
   - 每个请求发起时快照 `myToken = loadToken`，返回后校验 `myToken !== loadToken` 则**直接丢弃结果**；
   - 作用：防止「刷新 / 切换后，旧请求的下一页结果 concat 进新列表」造成串数据。

### 2.4 静默失败

预加载统一以 `silent = true` 调用 `loadMore`：

```ts
} catch (e) {
  // 预加载失败静默忽略，靠 onReachEnd 兜底重试；仅用户主动触底时提示
  if (!silent) {
    this.getUIContext().getPromptAction().showToast({ message: '加载更多失败，请稍后重试' });
  }
}
```

- 预加载（`silent = true`）：失败**不打扰用户**，因为用户还没滑到底，下次触底会自然重试；
- 触底加载（`silent = false`）：用户已到底在等，失败必须给 Toast 反馈。

### 2.5 内容高 `contentH` 的两种来源（2026-09-19 收口）

| 列表结构 | 能否实测 | 取法 |
|---|---|---|
| `Scroll + Column`（全量渲染） | ✅ 能 | 内容 `Column` 挂 `onAreaChange` → 实测值直接可用 |
| `List` / `WaterFlow`（虚拟容器） | ❌ 不能 | 容器自身高恒等于视口高、无内容总高读取接口 → **折算** |

折算口径统一收口在 `PrefetchGate.estimateWaterfallContentH(count, cols, contentW, rowGap)`：

```
内容高 ≈ ⌈条数 / 列数⌉ × ( estimateCardHeight(可用列宽) + 行距 )
estimateCardHeight(w) = 200 + w × 0.5625 × 0.5   // 文本区 ≈200 + 首图按 16:9 折算、按「约半数带图」打 0.5
```

**刻意不计顶部占位与底部留白** —— 折算偏小 → 剩余距离偏小 → 触发更早，宁可早取不漏取。
页面只提供 `count / cols / 内容宽 / 行距` 四个参数，卡高估算与折算公式不在页面里各写一份。

> 真机自证：折算后打一条 `[PREFETCH] <tag> geometry src=measured(...)/estimated(...) contentH=... viewportH=...`（每会话一条），
> 供按机型校准权重；滚动触发时另有 `FIRE` 日志。过滤方式：`hdc shell hilog | findstr PREFETCH`。

## 3. 五重兜底（预加载之外的保障）

预加载只是"提前量"，以下机制保证**任何情况下都能翻页、且不会失控**：

| # | 兜底 | 作用 |
|---|---|---|
| ① | `onReachEnd` | 保留原触底回调作兜底：预加载未命中（如大跨度跳滑）时仍能触发；锁会挡住与预加载的重复请求 |
| ② | 不满一屏直接预取 | `contentH ≤ viewportH`（内容不足一屏）时 Scroll **无法滚动**，`onScroll` / `onReachEnd` 都不触发 → 由 `onAreaChange` 主动预取下一页 |
| ③ | `loadingMore` 锁 | 见 §2.3，同时兜住 `onReachEnd` 与预加载的重复 |
| ④ | `stalledPages` 空轮保护 | 连续返回空页时计数，`≥ 3` 视为到底（`hasMore = false`），避免无限请求 |
| ⑤ | `onAreaChange` 实测 | 内容高 / 视口高随布局、分屏、窗口拖拽实时更新，阈值判定始终用最新几何 |

### 3.1 不满一屏的预取（关键）

```ts
/** 内容尺寸变化：记录内容高；不满一屏时直接预取下一页
 *  （Scroll 无滚动，onReachEnd / onScroll 均不触发） */
private onHomeContentAreaChange(oldValue: Area, newValue: Area): void {
  const h: number = newValue.height as number;
  if (this.homeFeed === HomeFeed.Following) {
    this.folContentH = h;
    if (this.folState === LoadState.Success && !this.folLoadingMore && this.folHasMore
      && this.folViewportH > 0 && this.folContentH <= this.folViewportH) {
      this.loadMoreFollowingThreads(true);
    }
  } else {
    this.homeContentH = h;
    if (this.loadState === LoadState.Success && !this.homeLoadingMore && this.homeHasMore
      && this.homeViewportH > 0 && this.homeContentH <= this.homeViewportH) {
      this.loadMoreHomeThreads(true);
    }
  }
}
```

### 3.2 视口测量与形态兜底

`onViewportAreaChange` 在记录视口高的同时，调用 `checkFormChange` 处理**分屏 / 自由窗口 / 折叠展开**：窗口宽高变化时刷新 `pageWidth` / `pageHeight` 标记，进而重算列数（`updateColumns`），保证预加载阈值判定与列数布局始终基于**真实窗口**而非 `display` 满屏口径。

## 4. 分页落地（三页面）

### 4.1 首页 `HomeTab` — 推荐 feed

```ts
private onHomeScroll(_x: number, y: number): void {
  this.homeScrollY = y;              // 记录浏览位置（切 feed 恢复用）
  ...
  if (this.loadState !== LoadState.Success || this.homeLoadingMore || !this.homeHasMore) {
    return;
  }
  const remaining: number = this.homeContentH - this.homeViewportH - y;
  if (remaining > HOME_PREFETCH_DISTANCE) {
    return;
  }
  if (Math.abs(y - this.homeLastPrefetchY) < 120) {
    return;
  }
  this.homeLastPrefetchY = y;
  this.loadMoreHomeThreads(true);    // 静默预加载
}
```

- 分页请求：`loadMoreHomeThreads(silent)` → `fetchHomePage(nextPage)`；
- 去重：`shownTids`（本会话）全量排除集 + 当前列表兜底；
- 有新内容时 `homeStalledPages = 0`，昵称后台校准（`enrichHomeInBackground`）不阻塞翻页；
- 结果写入 `CacheManager`（`CACHE_KEY.THREAD_LIST`）。

### 4.2 首页 `HomeTab` — 关注动态 feed

关注动态与推荐 feed **完全解耦**（各自独立测量值 / 状态 / 代际）：

| 状态 | 推荐 | 关注动态 |
|---|---|---|
| 内容高 | `homeContentH` | `folContentH` |
| 视口高 | `homeViewportH` | `folViewportH` |
| 偏移节流 | `homeLastPrefetchY` | `folLastPrefetchY` |
| 代际 token | `homeLoadToken` | `folLoadToken` |
| 加载锁 | `homeLoadingMore` | `folLoadingMore` |
| 页码 / 是否还有 | `homePage` / `homeHasMore` | `folPage` / `folHasMore` |
| 浏览位置 | `recommendScrollY` | `folScrollY` |

**关注动态分页是"本地切片"，零网络请求**（见 §5.2）。

### 4.3 吧主页 `ThreadList`

```ts
private onListScroll(_x: number, y: number): void {
  this.lastScrollY = y;
  const remaining: number = this.contentH - this.viewportH - y;
  ...
  if (this.loadingMore || !this.hasMore) {
    return;
  }
  if (remaining > THREAD_PREFETCH_DISTANCE) {
    return;
  }
  if (Math.abs(y - this.lastPrefetchY) < 120) {
    return;
  }
  this.lastPrefetchY = y;
  this.loadMore(true);
}
```

- 搜索态走独立分支（见 §6），与列表态解耦；
- 分页请求：`loadMore(silent)` → `fetchForumThreads(forumName, nextPage, selectedSort, false)`；
- 合并：`mergePage` 去重 + 推进 `page` / `hasMore` / `stalledPages`；
- 另有 `autoLoadMore`：首屏内容过短时循环补页至 `≥ 8` 条。

### 4.4 关注列表 `FollowList`

关注列表是 `List`（非 WaterFlow），**无内容总高接口**，故**按行数估算内容高**：

```ts
/** 关注列表行高估算（40vp 头像 + 上下内边距，用于预加载剩余距离估算） */
const FOLLOW_ROW_H: number = 76;

private onFollowListScroll(_x: number, y: number): void {
  if (this.editMode || this.loadState !== LoadState.Ready || this.loadingMore || !this.hasMore) {
    return;
  }
  // 内容高估算：顶栏占位(90) + 行数×行高 + 底部 padding(Spacing.xl≈24)
  const contentH: number = 90 + this.displayedList().length * FOLLOW_ROW_H + 24;
  const remaining: number = contentH - this.viewportH - y;
  if (remaining > FOLLOW_PREFETCH_DISTANCE) {
    return;
  }
  if (Math.abs(y - this.lastPrefetchY) < 120) {
    return;
  }
  this.lastPrefetchY = y;
  this.loadMore(true);
}
```

- **编辑态不预加载**（`editMode` 直接 return，避免多选取关时列表变动干扰）；
- 视口高由 `onViewportAreaChange` 实测回填 `viewportH`。

## 5. 关联优化（同批落地）

### 5.1 渲染层预加载窗口 `cachedCount`

预加载解决了"**数据**提前到位"，但 **ArkUI 组件的离屏构建**同样影响流畅度：默认 `cachedCount = 1` 时，快速甩滑下新格子出屏后才开始构建 → 空白 / 卡顿。

**修复（2026-09-19）**：按「列数 × 2」预建离屏格子，与首页 WaterFlow 同口径，**只改离屏构建窗口，不动几何 / 材质 / 滚动行为**：

```ts
// 预加载窗口（2026-09-19）：默认 1 个 FlowItem 太少，快速甩滑时新格子出屏后才开始
// 构建 → 空白/卡顿。按「列数×2」预建（2 列=4、3 列=6），只改离屏构建窗口。
.cachedCount(Math.max(2, this.homeColumns() * 2))
```

- `HomeTab`：推荐 / 关注动态两处 WaterFlow 均设 `Math.max(2, this.homeColumns() * 2)`；
- `ThreadList`：`Math.max(2, this.threadColumns() * 2)`（3 列=6、4 列=8）。

### 5.2 关注动态本地切片分页

关注动态的聚合结果**一次性拉回**后，翻页改为**本地切片**，翻页零网络请求：

```ts
/** 关注动态页：本地切片分页每页条数（聚合结果一次性拉回，翻页零请求） */
const FOLLOW_FEED_PAGE_SIZE: number = 20;

private async loadMoreFollowingThreads(silent: boolean = false): Promise<void> {
  ...
  const nextStart: number = this.folThreads.length;
  if (nextStart >= this.folAll.length) {
    this.folHasMore = false;
    return;
  }
  // 本地切片分页：聚合结果已在 service 端按时间倒序并去重，直接切片即可，零网络请求
  const appended: ThreadItem[] = this.folAll.slice(nextStart, nextStart + FOLLOW_FEED_PAGE_SIZE);
  ...
}
```

- 因此关注动态的"预加载"实际是**极低延迟的本地切片**，几乎瞬时到位；
- `applyFolSnapshot` 应用快照时保留已展示条数下限（`Math.max(folThreads.length, PAGE_SIZE)`），避免增量回调把已翻出的下一页"收回"导致跳动。

### 5.3 排序缓存预热

吧主页首次展示成功后，后台为**其它两个排序**预拉首屏并写本地缓存（`warmupSort`），使首次切换排序即命中缓存、无需冷启动等待：

- 触发：`warmupStarted` 标记首次成功展示后触发一轮；
- 跳过：对应排序已有有效缓存（`getWithTtlAllowStale` 且未过期）则跳过；
- 失败静默：预热失败不影响主流程，仅打日志。

### 5.4 图片侧（同批）：图片专用 Session + 全局并发闸门

本文解决的是「**帖子数据**提前到位」，但同一批还治理了「**图片**」侧的两个问题：

- **进帖洪峰挤占接口**：楼层全量渲染（`Scroll` + `Column` + `ForEach`）一次性涌出上百张图下载，与接口请求共用同一个 `rcp.Session` → 接口耗时 0.9s → 3.5~5.0s。改为**图片专用 Session**（独立连接池，`IMAGE_SEPARATE_SESSION` 可回退）+ **全局 8 并发 FIFO 闸门**（`ThreadDetail` 楼层宫格 / 头像接入）；
- **主线程同步 IO 掉帧**：`ImageCache` 的调试日志写盘 / `writeSync` 落盘 / 命中缓存时重复灰阶校验 / 缓存清理同步扫目录 → 全部收口（Z1~Z4 + 异步 prune + 日志总开关）。

> 详见 `docs/图片加载治理.md`（含「首次进帖宫格图不显示」竞态修复与真机回归清单）。

## 6. 吧内搜索态预加载

搜索态与列表态**解耦**（搜索可能在本吧列表尚未加载完就进入），且**按模式分派**：

```ts
private onListScroll(_x: number, y: number): void {
  ...
  if (this.searchMode) {
    // 搜索态与列表态解耦：不依赖吧内列表的 loadState，按模式分派（服务端翻页 / 本地续扫）
    if (remaining <= THREAD_PREFETCH_DISTANCE && Math.abs(y - this.lastPrefetchY) >= 120) {
      this.lastPrefetchY = y;
      this.searchNextBatch();
    }
    return;
  }
  ...
}
```

### 6.1 取下一批：`searchNextBatch`

统一入口，按模式分派：

- **服务端模式**（`searchServerMode`）→ `searchServerFetch(false)`（服务端分页翻页）；
- **本地模式** → `searchScan(searchThreads().length + SEARCH_BATCH_RESULTS)`（批量补扫吧内分页）。

### 6.2 自动续载：`maybeAutoContinueSearch`（修复"下滑加载不出来"）

**问题**：结果不满一屏时用户**根本无法滚动** → `onScroll` / `onReachEnd` 都不触发 → 永远等不到下一批。

**修复**：只要满足其一就主动补下一批，不必等用户再滑：

- **视口没被填满**（`contentH ≤ viewportH + 40`），或
- **用户就停在结果底部**（`remaining ≤ THREAD_PREFETCH_DISTANCE`）；

用 `SEARCH_AUTO_CONTINUE_MS = 120ms` 延时给 UI 一帧渲染机会；用户上滑离开底部后自然停止，因此不会无谓持续拉取。

- 服务端模式自动续载有上限 `SEARCH_SERVER_AUTO_MAX = 300` 条，防 `has_more` 异常时后台无限翻页，超出后仅由用户下滑驱动。

### 7.3 事件绑定

| 事件 | 用途 |
|---|---|
| `onScroll` | 读 `PrefetchGate.absoluteY(scroller)` 真值 + `gate.should(...)` 判定 + 触发预加载（**不使用回调入参**） |
| `onAreaChange`（内容） | 回填 `contentH` + 不满一屏直接预取（全量渲染分支才有内容高） |
| `onAreaChange`（视口） | 回填 `viewportH` + `checkFormChange` 形态兜底 |
| `onReachEnd` | 触底兜底（锁去重）；ThreadList 另有尾部三态提示浮出 |

`Search.ets` 的具体挂点：`Scroll` 挂 `.onScroll((x, y) => this.onContentScroll(x, y))` + `.onReachEnd(() => this.loadMoreCurrent(false))`；
内容 `Column`（含 `HEADER_TOP_SPACE` / `BOTTOM_BAR_SPACE` 让位，即真实可滚动高）挂 `.onAreaChange(... onContentAreaChange ...)`；
根 `Stack` 在其既有 `onAreaChange` 内回填 `viewportH`（必须放在 `refreshFormMetrics` **之前**——后者宽高同值时会提前 `return`）。

## 8. 维护须知

1. **新增帖子流列表**：按本方案接入，至少包含五件事 ——
   - 滚动容器挂 `Scroller`（`Scroll(scroller)` / `List({ space, scroller })`），并把它传给判定；
   - 建一个 `PrefetchGate`（阈值按页面节奏定，节流默认 120vp）并挂在实例字段上；
   - `viewportH` 由滚动容器 `onAreaChange` 回填；`contentH` 能实测则实测（全量渲染分支），虚拟容器按 §2.5 折算；
   - 请求带 `loadToken` 代际校验，刷新 / 切 feed / 换列表时 `gate.reset()`；
   - 保留 `onReachEnd` 兜底 + `stalledPages` 空轮保护。

   ❌ **三条禁令**：① 用 `onScroll` 回调入参当绝对偏移；② 在页面里另抄一份「剩余距离 + 节流」判断；
   ③ 在页面里另写一份卡高 / 内容高折算公式（口径只在 `PrefetchGate` 维护，页面只提供参数）。

2. **阈值调大**会让预加载更早（更不易卡，但更早消耗流量 / 请求）；**调小**则更省，但快速甩滑可能追不上。1200vp 是本项目真机回归后的定值。

3. **不要用 `@State` 存测量值**：`contentH` / `viewportH` 等均为**普通字段**（`private` 而非 `@State`），因为 `onAreaChange` / `onScroll` 是高频回调，用 `@State` 会触发无谓 UI 重建；`PrefetchGate` 内部同样只存普通字段。

4. **静默与提示的边界**：预加载一律 `silent = true`；仅 `onReachEnd` 触底路径允许 `silent = false` 弹 Toast。

5. **关注动态是本地切片**：其 `loadMore` 走 `folAll.slice()`，扩展时注意 `applyFolSnapshot` 的"只增不减"快照合并约束。
