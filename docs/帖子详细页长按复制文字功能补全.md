## 2. 现状（代码事实，行号已按 2026-09-23 源码校正）

### 2.1 正文区渲染方式

正文类内容统一走 `@Builder RichTextContent(fragments, fallbackText, fontSize, fontColor, lineHeightVal)`：

| 文件 | builder 定义 | 调用点 |
|---|---|---|
| `ThreadDetail.ets` | `4107` | 楼主正文 `3445`、楼层正文 `3744`、楼中楼评论正文 `3826` |
| `SubPostDetail.ets` | `1161` | 父楼层正文 `841`、楼中楼评论正文 `991` |

builder 内部为：

- 有 `fragments` 时 → `Text() { Span / ImageSpan }`（`ThreadDetail.ets:4121`，属性链 `4175-4178` / `SubPostDetail.ets:1171`，属性链 `1225-1228`），并挂 `.fontSize().fontColor().lineHeight().width('100%')`
- 无 `fragments` 时 → 纯文本兜底 `Text(fallbackText)`（`ThreadDetail.ets:4180` / `SubPostDetail.ets:1230`）

两个文件的 `RichTextContent` **结构完全同构**（同一套 Emoji 预取 + Span 分支 + 兜底分支），所以改动可以逐行对齐复制。

### 2.2 帖子标题

- 帖子标题是**独立 `Text`**，不在 `RichTextContent` 内：`ThreadDetail.ets:3439` 的 `Text(this.detail!.title)`，位于 `@Builder PostHeader()`（`3399`）的楼主卡中，其后紧跟正文 `RichTextContent`（`3445`）。
- 该 `Text` 只挂 `.fontSize().fontWeight().fontColor().width('100%')`，**没有 `onClick`、没有自定义手势**，加选择能力无冲突面。
- `SubPostDetail` 是楼中楼二级页，**没有帖子标题**，故该文件只涉及正文两处（`1171` / `1230`）。

### 2.3 关键现状点

- **上述所有 `Text` 都没有设置 `copyOption`**（2026-09-23 全工程检索零命中）→ 默认 `CopyOptions.None` → 当前长按没有任何反应（这正是本需求要补的点）。
- `ThreadDetail` 三个正文调用点共用一个 builder，**改一处即三处生效**；`SubPostDetail` 同构，同样只需改一处。
- 楼层容器为 `Scroll(scroller) { Column { PostHeader, ForEach(this.floors) → FloorCard } }`（`ThreadDetail.ets:2539` 分栏左栏 / `2623` 竖屏），**全量 ForEach、非 LazyForEach**，不存在视口回收导致选中态错乱的问题。
- 长按通道：正文与标题区**当前为空**。2026-09-23 修正：`ThreadDetail.ets:4675` 存在一个 `LongPressGesture(350ms)`，但它是**底栏收藏钮的「长按收藏并归类」**，不在正文/标题区，与文本选择无冲突面。
- 内容区内已存在的点击交互：
  - 作者名 `Text.onClick`（进个人主页，`3411`；SubPostDetail `831` / `953`）—— **本次不触碰**
  - 链接 `Span.onClick`（`ThreadDetail.ets:4161` / `SubPostDetail.ets:1211`，弹"是否跳转链接"确认卡片）
  - 图片 `Grid.onClick`（`ThreadDetail.ets:4041`，图片预览）
  - 内联楼中楼点赞钮 `onClick`（`ThreadDetail.ets:3858`，透明背景钮，紧邻评论正文但在其外）
  - 「查看全部 N 条回复」行 `onClick`（`ThreadDetail.ets:3888`，独立行，不在正文上）

### 2.4 2026-09-23 复核：09-12 后新增的代码事实

1. **分栏模式（splitMode）自动覆盖**：分栏左右两栏共用 `PostHeader` / 楼层 builder，正文 builder 改一处两栏自动生效，无额外改动；真机回归需覆盖（见 §6）。
2. **内联楼中楼评论自动受益**：`3826` 的楼中楼评论正文走同一 builder，加属性后自动获得选择能力；其旁点赞钮（3858）与作者名（3788）的 `onClick` 均在正文 `Text` 之外，R4 结论不变。
3. **纯图回复兜底分支部分失效**：2026-09-20 去冒号改造后，楼中楼纯图回复**不再调用** `RichTextContent`（`fragments>0 || content.length>0` 才调）。兜底 `Text`（4180/1230）仍加同款属性（保持一致性、成本为零），但需知晓其在楼中楼调用点已基本不可达。
4. **分区上屏 + 加载过渡叠加窗口**：数据到达后有 `floorsReady` 50ms 延迟构建 + 内容 240ms 上浮进场。`copyOption` 是静态属性不受动画影响，但动画进行中长按列为真机观察项（R8）。
5. **小窗/自由多窗**：`<600` 手机档单列 Scroll 同样适用；R3 的长按与滚动竞争在窄屏下更易暴露，并入回归。

## 3. 平台能力（已对本机 SDK 实测核实，非推测）

以下 API 均已对本机 SDK（API 26.0.0，`compatibleSdkVersion` 同）实测核实，非推测。

### 3.1 `Text.copyOption`

- 签名：`copyOption(value: CopyOptions)`，`text.d.ts:677`，API 9 起。
- **默认值 `CopyOptions.None`**（`text.d.ts:668`），必须显式开启。
- `CopyOptions`（`enums.d.ts:3229`）：`None=0` / `InApp=1`（仅应用内） / `LocalDevice=2`（本机跨应用，推荐） / `CROSS_DEVICE=3`（API 12 起废弃）。
- 设为 `InApp` / `LocalDevice` 后（`text.d.ts:654-666`）：
  - 长按弹出文本选择菜单，含**复制 / 全选**；
  - 选中文本默认可拖拽，可设 `draggable(false)` 关闭（`text.d.ts:695`，属性段写默认 `false`，与 copyOption 段说明不一致，建议显式设置）；
  - Ctrl+C 复制需额外设 `textSelectable(SELECTABLE_FOCUSABLE)`（手机端不需要）；
  - **`Text` 会监听 `onClick`，且手势事件为非冒泡事件** → 父容器若依赖点击需改用 `parallelGesture`；
  - 卡片（widget）没有长按事件，本工程不涉及。
- 相关可选项（均在本地 SDK 中存在）：
  - `onCopy(callback: (value: string) => void)`（API 11，`text.d.ts:819`）→ 可弹"已复制"提示。**2026-09-23 拍板：系统选择菜单点「复制」后系统侧可能自带成功提示（待真机确认），故先裸加 `copyOption` 观察，若无系统提示再补 toast**
  - `onWillCopy(callback: Callback<string, boolean>)`（API 26.0.0，`text.d.ts:834`）→ 复制前拦截。注：其回调拿到的是已拼好的字符串，无法把 ImageSpan 还原成 `[微笑]` 文本，救不了 R1
  - `caretColor` / `selectedBackgroundColor`（`text.d.ts:879` / `891`）→ 可把默认选中色 `#007DFF` 换成品牌蓝。**2026-09-23 拍板：不改，按系统默认**
  - `editMenuOptions`（`text.d.ts:1160`）/ `bindSelectionMenu`（`text.d.ts:1019`，长按响应 600ms，优先于 `bindContextMenu` 的 800ms）→ 自定义选择菜单项
- API 20 起复制会向剪贴板写入 HTML 格式内容；含子组件时**仅 `Span` / `ImageSpan`** 支持 HTML 粘贴板内容。

### 3.2 `SelectionContainer`（跨节点选择容器）

- 本机 SDK 已存在：`ets/api/@ohos.arkui.components.SelectionContainer.d.ts`，**全部接口 `@since 26.0.0`**，并由 `@kit.ArkUI` 统一导出（`import { SelectionContainer } from '@kit.ArkUI'`）。
- 作用：让容器内**多个 `Text` 的文本可跨节点连续选中**并按视觉顺序拼接复制（`textJoinStyle` 默认 `NEWLINE`）。
- 属性：`copyOption`（默认 `InApp`）、`caretColor`、`selectedBackgroundColor`、`textJoinStyle`、`enableHapticFeedback`、`bindSelectionMenu`、`editMenuOptions`、`onTextSelectionChange` / `onWillCopy` / `onCopy`。
- 限制（重点）：
  - **仅 `Text` 组件的文本参与**选中与拼接；`Repeat` 下的文本不支持（本工程未用 `Repeat`）。
  - **不显示放大镜**、**不支持拖拽**、**不支持图形变换**（容器及其内部 `Text` 均不支持）。
  - 容器内 `Text` 的 `caretColor` / `bindSelectionMenu` / `editMenuOptions` 无效，始终用容器配置；`copyOption` / `selectedBackgroundColor` 以 `Text` 显式设置为优先。
  - 默认布局是 `Stack`，需要别的布局要自己嵌容器。

## 4. 方案设计

### 4.1 方案对比

| 维度 | A：正文可选中（最小改动） | B：整楼跨节点选中 | C：一键复制整楼文字 |
|---|---|---|---|
| 做法 | 在 `RichTextContent` 内的两个 `Text`（含 Span 分支与兜底分支）加 `.copyOption(CopyOptions.LocalDevice)`，配套 `.draggable(false)`；帖子标题 `Text` 同样处理 | 楼层卡外层包 `SelectionContainer`，让正文 + 楼中楼回复等可连续选中、拼接复制 | 通过 `editMenuOptions` / `bindSelectionMenu` 在选择菜单追加"复制本楼文字"，自己用 `fragment.text` 拼串写剪贴板 |
| 改动量 | 2 个文件、各 1 个 builder + 1 处标题（约 10 行） | 中等（需增加容器包裹层） | 中等（拼串逻辑 + 菜单 API） |
| 布局影响 | **零**（`copyOption` 不改布局） | 需验证（`SelectionContainer` 默认 Stack 布局，需要显式嵌套容器保持原有布局） | 零 |
| 体验 | 局部选字复制（贴吧/知乎式） | 跨正文与回复连续选择，更完整 | 复制结果最完整可控（可带上表情原文"\[微笑\]"） |
| 主要风险 | 表情丢失（已接受）、链接点击待验 | 无放大镜、长按与滚动的竞争、API 26 新组件需真机回归 | 与 A 共享同一个长按，需确认菜单优先级 |

### 4.2 本次采用的方案

**本次实施 = 方案 A（含用户追加的帖子标题与 SubPostDetail 全量同步）**，原因：

1. 用户已确认范围为"正文 / 回复 / 楼中楼回复（+ 帖子标题）"，**不含作者名**；方案 B 的跨节点选中天然会把作者名一起纳入（虽然可通过给作者名 `Text` 设 `copyOption(CopyOptions.None)` 排除，但属额外复杂度）。
2. A 的布局影响为零，风险面最小，可作为第一版交付。

方案 B / C 记录为**后续可选增强**，不在本次范围。

### 4.3 方案 A 落地要点（三处，缺一不可）

- Span 分支 `Text`（属性链 `4175-4178`）与纯文本兜底 `Text`（`4180`）**两个都要改**，否则无 `fragments` 的纯文本楼层仍不可选。

#### 4.3.2 `ThreadDetail.ets` → 帖子标题 `Text`（`3439`）

- 单独一处改动：`Text(this.detail!.title)` 同样挂 `copyOption`（该 `Text` 无 `onClick`，无手势冲突）。
- 加完后"标题"与"正文"是两段独立可选区域，长按标题只选中标题、长按正文只选中正文，符合预期。

#### 4.3.3 `SubPostDetail.ets` → `RichTextContent` 两个 `Text`（`1225-1228` / `1230`）

- 与 4.3.1 **完全相同**的改动，逐行对齐，保证两个页面行为一致，避免"同一个 App 有的地方能选、有的不能选"。

#### 4.3.4 统一属性清单（示意，非最终代码）

#### 4.3.5 不触碰的部分（避免误伤）

## 5. 风险与硬限制

| 编号 | 问题 | 影响 | 处理 |
|---|---|---|---|
| R1 | **复制结果丢失表情**。表情走 `ImageSpan(PixelMap)`（`ThreadDetail.ets:4125` / `SubPostDetail.ets:1175`），选中时是图片不是文字；且 `ImageSpan.alt` 签名为 `alt(value: PixelMap)`（`image_span.d.ts:168`）**只接受 PixelMap，无法塞入"\[微笑\]"文本 alt** | 复制出的文本缺少表情占位 | **用户已接受**。若将来不接受，只能走方案 C 自建拼串 |
| R2 | 链接 `Span.onClick` 与长按选择共存（`ThreadDetail.ets:4161` / `SubPostDetail.ets:1211`） | 若点击被吞，链接无法打开 | 理论单击仍触发、长按优先选择（长按约 500ms），**待真机验证**；退路是用 `bindSelectionMenu` 补"打开链接"项 |
| R3 | 长按选择 与 `Scroll` 滚动竞争 | 可能出现滚动/选择互相干扰 | `.draggable(false)` 降低冲突面，**待真机验证**"长按后拖选择手柄页面不滚"；小窗窄屏（<600）下更易暴露，并入回归 |
| R4 | `Text` 手势非冒泡（`text.d.ts:661`） | 依赖父级点击的交互会失效 | 本次涉及的 `Text` 全部**无父级 `onClick`**（标题、正文、楼层卡、详情卡皆无；内联楼中楼点赞钮 3858、「查看全部回复」3888 均在正文 Text 之外），无影响；后续若给卡片加点击需改用 `parallelGesture` |
| R5 | 长列表成本。楼层是全量 `ForEach`（可能上百层），每个正文 `Text` 都注册选择能力 | 长列表滚动帧率 / 内存 | **待真机验证**（长帖滚动、内存） |
| R6 | `RichTextContent` 的 `ForEach` key 含 `_r/_f/_w`（`ThreadDetail.ets:4169-4173`），表情预取完成会重建 Span | 极少数情况下正在选择时被中断 | 影响很小，本次不处理；如需可后续稳定 key |
| R7 | 帖子标题开启选择后，长按标题弹菜单 | 用户可能误以为长按标题有其他含义 | 低风险，行为与系统一致即可，无需额外处理 |
| R8 | **加载过渡动画进行中长按**（2026-09-23 新增）：数据到达后有 `floorsReady` 分区构建 + 内容 240ms 上浮进场 | 动画中长按理论上无冲突（`copyOption` 为静态属性），仅观察 | 真机回归项：内容淡入/上浮动画进行中立即长按，选择菜单无异常 |
