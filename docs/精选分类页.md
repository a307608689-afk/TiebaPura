# 精选分类页（GoodCategoryPage）经验汇总

> 2026-09-20 ~ 09-21 完整落地记录。十六轮迭代定稿，全部结论经真接口探针实测 / 真机反馈 / 构建验证（`tools/build.ps1` BUILD SUCCESSFUL）。

---

## 1. 功能定义

- **入口**：吧主页（ThreadList）底栏官方槽位「精选」钮 **长按 350ms** + 轻振动，静默进入（无 Toast）；兜底路径 `SortTabsBuilder` 的 `Button('精选')` 同款长按。点按路径（切排序）零改动，布局/材质/选中态一行不动。
- **转场**：页面 `pageTransition()` 自下而上——进场 `slide(SlideEffect.Bottom)` 280ms，返回向下收回 240ms。
- **页面**：顶部精选二级分类胶囊行（可横滑）+ 帖子瀑布流；切分类带左右对向平移动画；支持左右滑手势切换分类。

---

## 2. 协议实测（tools/good_classify_probe.js）

**背景**：外部 proto 仓库（n0099 / Gan332 / min09577 TiebaLite）拿不到权威字段号，最终全部用自写 Node 探针跑真接口实测。

### 2.1 字段号结论

| 位置 | 字段 | 说明 |
|---|---|---|
| 响应侧 `good_classify` | **挂在 forum（FrsForumMessage）field 21** | **不在 DataRes 顶层**（递归扫 DataRes 找不到就是因为它嵌在 forum 里） |
| Classify 项 | `class_id`(3) / `class_name`(4) | 实测响应只下发这两项；`name`(1)/`id`(2) 兼容解析但不依赖 |
| 请求侧过滤 | **cid = field 5** | Gan332/Lite proto 的 `class_id = field 23` **实测不过滤，勿用**；cid 不传 = 全部 |

### 2.2 探针方法论（可复用）

1. 复用工程已有 `tools/subpost_img_probe.js` 的手工 protobuf 编解码模式（`fieldsOf`/`varField`/`strField`/`lenField`）。
2. 先按猜测字段号 dump 顶层 → 找不到就**递归扫描**子消息（深度 ≤3）。
3. 形态判定太严会漏（第一次没识别出 9 个分类），最后是靠打印 forum 字段分布 `f21×9` 人工定位，再直接 dump 原始项确认内容与官方截图一致。
4. **guest（无登录态）响应就下发 good_classify**，无需登录态即可探。
5. 验证请求侧语义：同请求带/不带 cid 对比首帖与条数（百合吧 cid=1：17 条 → 8 条，首帖不同 = 过滤生效）。

## 3. 服务层改造（TiebaService / Decoder / Schema）

- `TiebaProtoSchema.ets`：`FrsForumMessage` 增 `goodClassify?: GoodClassifyMessage[]`；新增 `GoodClassifyMessage { name?, id?, classId?, className? }`。
- `TiebaProtoDecoder.decodeFrsForum`：field 21 必须在 wireType===2 分支**最前面**走 `readBytes → decodeGoodClassify`（嵌套消息），否则会落进 readString 通道产出乱码。
- `TiebaService`：
  - `fetchForumThreads` 加第 5 个可选参 `goodClassId`（仅 `>0` 时 `set('cid')`，老调用点零影响）；`requestForumThreadsProto` 同步透传。**modern JSON 兜底路径不支持 cid**，按「全部」回落。
  - is_good 响应自然落分类缓存 `cachedGoodClassify` / `cachedGoodClassifyKw`（kw 校验防串吧），`getCachedGoodClassify(kw)` 读取——首屏一次请求两用（列表 + 分类清单）。
  - `prefetchGoodFirstPage` / `fetchGoodFirstPageCoalesced`：复用 `pendingForumPrefetch` 在途合流 map（key `${kw}_good`，TTL 10s 一次性消费）。
  - `fetchGoodCategoryThreads`：切分类专用，**仅走 proto 路径**（JSON 路径无 cid 语义）。
  - 空结果：`fetchForumThreads` 对整链路空结果 throw「没有可显示的帖子」→ 页面 catch 里按 Empty 呈现（不是 Error）。

## 4. 页面架构（十六轮演进定稿）

### 4.1 整体结构

```
build Stack
├── ContentLayer Stack  ← 左右滑 parallelGesture 挂这里（普通容器！）
│   ├── SlotLayer(0)   ← 常驻槽位：Refresh{WaterFlow} + visibility + translate
│   ├── SlotLayer(1)   ← 常驻槽位：同上，角色轮换
│   └── 状态覆盖层（Loading/Empty/Error，不透明，盖住槽位）
├── 渐显带 scrim（120vp 线性渐变，底部透明）
├── 官方光感胶囊行（Tabs 空壳 + 逐枚 segFlat）
└── 左上角「吧名 · 精选分类」小胶囊 chip
```

### 4.2 顶部（第 8/9 轮定稿：无返回钮无吧名）

- 满宽**渐显带**（120vp，页面底色→透明线性渐变）+ 胶囊行；`GOOD_TITLE_BAR_HEIGHT=88`、scrim 120。
- 返回靠系统侧滑 + 手势；左上角仅一枚小胶囊 chip。
- 内容从胶囊行之下开始（WaterFlow 顶让位占位 FlowItem），滚动时卡片从渐显带下穿过（沉浸）。

### 4.3 胶囊官方沉浸光感（第 11 轮定稿）

- **空 tabBar 壳**：`Tabs{barPosition:End}` + 一个空 `TabContent`（tabBar 空壳），拿到官方 tab 背板光感；**`barBackgroundBlurStyle` 必须显式 `BlurStyle.NONE`**（不写会有默认值）；壳 `hitTestBehavior(None)` 只当背板。
- 胶囊本体：`Scroll{Row}` 横滑（足迹同款），逐枚 `Text.systemMaterial(ImmMaterial.segFlat(选中态))`，fontSize 13 / padding 16·7；选中 `font_emphasize` + Bold。
- 低版本（不支持 ImmMaterial）真模糊兜底：`backgroundBlurStyle` 路线，几何一致。

### 4.4 双常驻槽位角色轮换（第 14 轮定稿，根治切分类闪帧）

- `ds0/ds1` + `scroller0/1` + `slotCid[slot]` **永久存活**（visibility None 切换，组件状态与图片保留）——切回看过的分类槽内现成数据，零重建零闪秒切。
- 切分类：目标分类写**非活跃槽**（离屏构建好）→ `applySwitchDisplay` 起 in/out 对向平移动画（320ms springMotion）→ 落定只换 `activeSlot`，不重建任何列表。
- 快照 LRU：cap 8（Map delete+set touch），条数不设上限（存的是纯数据 ThreadItem，位图由 ImageCache 管）。
- **最大坑（第 15 轮真因）**：`applySwitchDisplay` 漏赋 `inSlot/outSlot`，activeSlot 仍是 -1 → 双槽全 None 整页空白。**教训：槽位/角色类重构，起动画前必须显式赋值全部角色字段（inSlot/outSlot/activeSlot）**。
- `loadMore/handleRefresh` 加 `inSlot !== -1` 守卫，只操作活跃槽；`loadState` 覆盖层不透明，盖住槽位避免旧数据透出。

### 4.5 左右滑手势（第 16 轮补回）

- **挂点铁律：`parallelGesture(PanGesture{fingers:1, Horizontal, distance:30})` 必须挂在外层普通容器上**（现在的宿主是 ContentLayer Stack）——挂 Refresh 上 parallelGesture 不触发（第 12 轮实测）。
- 语义：`offsetX > 80` 右滑 = 上一个分类，`offsetX < -80` 左滑 = 下一个分类，走 `selectCategory` 统一链路；「全部」/最后一个分类边界忽略。
- **滑动锁**：`onActionStart` 即 `swipeLock = true`，End/Cancel 后 **250ms 延迟解锁**——横向 Pan 期间抬指卡片仍会收到 onClick，不锁会误开帖子；卡片 onTap/onComment `if (!swipeLock)` 放行。
- **第 16 轮教训：整页大重构（write_to_file 级）会把"旁挂能力"整段弄丢**——重构后必须对照旧版功能清单逐项核对。

### 4.6 列数适配（第 4/10 轮）

- `goodColumns()` 逐字复刻 `ThreadList.computeThreadColumns`：窗口三档闸门（<600→1、600~840→2、≥840→3）→ isWideBarFullscreen 白名单 → columnMode 覆盖 → 大折叠/阔直屏分支；`columnsTemplate` 单点同源生成，严禁直绑列数变量。

### 4.7 首屏加速（三级保障）

1. ThreadList 排序冷缓存预热（`FORUM_LIST_kw_2`，5min TTL）→ 进页磁盘缓存直出（stale-while-revalidate，头部 tid 比对免重建）。
2. ThreadList 精选钮 Down 起 60ms 计时预取（Up/Cancel 撤销，`goodPrefetchDone` 每进吧一次，有新鲜缓存跳过）→ 长按期间请求已在途 → 进页合流消费。
3. 兜底一次 RTT（`fetchGoodFirstPageCoalesced`）。

### 4.8 转场 RouteType（第 7 轮定稿）

| 场景 | 配置 |
|---|---|
| 从吧主页进入 | `PageTransitionEnter({type: Push})` `slide(Bottom)` 280ms |
| 从帖子详情返回 | `PageTransitionEnter({type: Pop})` 1ms（无动画，用户第 5 点） |
| 返回吧主页 | `PageTransitionExit({type: Pop})` `slide(Bottom)` 240ms |
| 去帖子详情 | `PageTransitionExit({type: Push})` 1ms（第 6 点：去掉多余的右退出） |

## 5. 坑清单（按轮次沉淀，全部真机/构建实证）

1. **animateTo 只驱动 @State**：普通成员变量改了不动画，位移偏移量必须 @State。
2. **Refresh `$$refreshing` 双向绑定下禁加 `if (this.refreshing) return` 守卫**：会卡死刷新态（onRefreshing 里先置 true 再 return = 永远转圈）。
3. **切分类必须走 proto**：modern JSON 路径无 cid 语义，切过去还是全部的内容。
4. **`pageTransition()` 必须声明在 @Entry struct 体内**（与 aboutToAppear 同级的特殊方法），放文件顶层报 `Cannot find name 'pageTransition'`；方向用 `.slide(SlideEffect.Bottom)`——`PageTransitionOptions.type` 是 RouteType（None/Push/Pop），**不是方向枚举**。
5. **WaterFlow 是 `rowsGap` 不是 `rowGap`**。
6. **本地 IDataSource 必须实现 `registerDataChangeListener` / `unregisterDataChangeListener`**，缺了构建报错。
7. 空结果按 Empty 呈现（识别 throw message「没有可显示的帖子」），别当 Error。
8. **componentSnapshot 对 WaterFlow 截图不可靠**（第 13 轮弃用快照层，改双常驻槽位）。
9. **Refresh 上挂 translate 不参与 animateTo、挂 parallelGesture 不触发**——位移与手势一律上移到外层普通容器。
10. 切过场是**单次两页过场**：动画期间再切要忽略（`switching` 守卫），否则 offset 状态机错乱。
11. 滚动容器内横向手势必须 `parallelGesture`（普通 gesture 被滚动独占）。
12. 横向 Pan 期间卡片 onClick 仍会派发 → 起手锁 + 延迟解锁。
13. 静默刷新先比对头部 tid，相同则免重建。
14. 单 WaterFlow + reload 必然全量重建闪帧 → **双常驻槽位根治**。
15. 槽位/角色类重构：起动画前 inSlot/outSlot/activeSlot 必须显式赋值。
16. **整页大重构后必须对照旧版功能清单逐项核对**——手势这类旁挂能力最容易整段丢失（第 16 轮左右滑失效的真因）。

1. 长按「精选」自下而上进页；快速点按切排序不受影响
2. **左右滑切换分类**（生效、方向正确、边界忽略、滑动中不误开帖子、不干扰竖滚/下拉）

7. 去详情无退出动画、详情返回无进场动画、回吧主页仅向下收回
8. 点赞/分享/下拉刷新/触底加载/3 空轮熔断
